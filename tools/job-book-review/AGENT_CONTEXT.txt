READ THIS FIRST
- This is a browser-only Job Book Review tool. PDFs and review progress stay on the user's device; PDFs are never uploaded.
- The working directory is tools/job-book-review/.
- The local preview URL is normally http://localhost:4173/tools/job-book-review/.
- Do not commit, push, open a pull request, publish, or discard existing work unless the user explicitly asks in the current conversation.
- The repository may already contain unrelated user changes. Preserve them.
- IMPORTANT: Whenever you change this tool, update this file in the same change. Record the version, date, files changed, behavior changed, and validation performed. Tell any subagent or collaborating agent to do the same.

PRODUCT GOAL
- The goal is to review EVERYTHING in EVERY loaded document. DECISION (2026-10-10): only ROMC and SIF have their fields reviewed individually; every other document (including Generator Alignment and the QC forms) is page review only (one whole-page item per page, targetKey page-review, kind 'document'). In ROMC/SIF any page with no reviewed field also gets a page review.
The tool supports a complete Job Book Review. It is not ROMC-only: ROMC, SIF, and future job-book source types should use the same guided review experience. A reviewer works through fields one at a time, sees the source field and the required comparison target, and marks each target Verified or Issue.

CURRENT REVIEW RULES
- Review every populated, non-N/A field in ROMC and SIF. Skip toggles on the launch card (state.skip, persisted in the session): Dates (default ON), Initials, Names, Company, Version numbers, Yes/No answers (default OFF). Skipped fields never enter the review queue.
- One source form field is one field even if its value has commas, semicolons, ampersands, or several serial-like pieces. Punctuation must never create additional reviews.
- Create another review only for a distinct verification target: a different document or a different required area in the same document.
- Repeated appearances within one target area do not create additional reviews.
- Keep review marks and the current review location across refreshes.
- Verified advances to the next unresolved target. Issue marks the item immediately and shows the optional note panel; the note autosaves (400 ms debounce, on document change, on step change/close) with no Save/Cancel buttons. Exactly one note per review item (keyed by reviewKey), editable at any time; notes are attached to a selected document. Removing an Issue hides its note from issue reports but preserves it for re-applying the Issue.
- Issue exports are available as Excel-compatible XML and formatted PDF.

CURRENT UX
- The prominent "Start Job Book Review" card appears before Results.
- It supports All job book fields, ROMC fields only, and SIF fields only. The chosen scope and review position are persisted.
- The review overlay shows the source on the left and EVERY required target document side by side (up to 3 target panes, each with a numbered label). The tabs (and keys 1-3) still choose which target Verified/Issue applies to; that target's pane is outlined and labelled in blue, verified/issue labels are green/red. Manual-check targets have no pane.
- Each step has a target-specific tip.
- Buttons show their keyboard shortcuts. Viewer controls support normal scrolling, Ctrl+wheel zoom, Shift+wheel horizontal pan, and middle-mouse drag panning.
- Source-field highlights use the exact AcroForm rectangle when available; only the relevant source page should be highlighted.
- Review order is source kind (ROMC then SIF) and then visual top-to-bottom, left-to-right within each PDF page.

JOB BOOK ANSWERS CSV AND COMPARISON
- "Export CSV" (button #snc-snapshot, formerly "Export answers CSV") writes every ROMC/SIF field: Source, Section, Field name, Label, Value, State (Populated / N/A / Blank), Page, Category (date / initials / name / company / yesno / empty), Review (verified / issue / pending / empty when skipped), Issue note, Document.
- Blank fields are recorded at extraction (doc.blankFields, text/choice fields only; checkboxes and radios are ignored). Older saved documents without blankFields are re-extracted once on restore.
- The compare card (above Review status) uploads a previous answers CSV (#snc-compare-file). It is kept in localStorage key snc-compare-baseline and compared with the loaded job book by Source + Field name + occurrence.
- Summary: Fields / Populated / N/A / Blank counts (previous vs current) plus lists: blank now, filled now, N/A now, filled from N/A, different value, only in current, only in previous. Dates are always ignored; initials/names/company/yes-no follow the Skip toggles for the different-value list.

PERSISTENCE AND VIEWER RELIABILITY
- Original PDF blobs, extracted text, form fields, source rectangles, selected reference, review position, and review scope are saved in IndexedDB (database: snc-persisted-documents).
- Older persisted documents lacking source rectangles are re-extracted once after restore.
- Review marks and notes are stored in browser localStorage, keyed to the reference document.
- viewer.js retains active pdf.js document leases so cache eviction cannot destroy an open viewer document. Do not remove this protection without an equivalent lifecycle solution.
- pdf.js uses the standard-font data URL to reduce harmless missing-font warnings. Embedded-font "TT" warnings can still occur and are usually not the cause of a failed highlight.

KEY FILES
- index.html: page structure, styles, version tag, cache-busted script URLs.
- script.js: document ingestion/extraction, IndexedDB persistence, target rules, Job Book Review queue, exports, and UI rendering.
- viewer.js: overlay, PDF rendering/cache, highlights, review controls, keyboard and pointer interactions.
- tool.json: tool metadata.
